# フィラートークンは数学と音韻検索を改善するか：記事構成案

この記事では、意味のない文字列を質問と回答の間に置くと精度が上がるという報告を、公開算術タスクで追試する。その結果を確認したうえで、同じモデルとフィラーを音韻検索の並べ替えに適用する。数学で効果が出たか、音韻検索でも効果が出たかを、それぞれ測定結果に基づいて述べる。

## 1. 「意味のない文字を足すと精度が上がる」という報告

- [joisino氏の紹介記事](https://joisino.hatenablog.com/entry/filler)をきっかけとして示す。
- フィラーは、質問と回答の間にあらかじめ置く数列や省略記号などであることを、小さなプロンプト例で説明する。
- 思考過程を文章で生成させるCoTとの手続きの違いを説明する。精度の向上だけから内部の計算方式を特定できるとは述べない。
- 「300個」はモデルの300トークンと同義ではない。文字列の作り方と実際のトークン数を区別する。

## 2. 何を追試するか

- [Greenblatt氏の原典](https://www.lesswrong.com/posts/NYzYJ2WoB74E6uj9L)には、生成算術問題と競技数学問題の評価がある。
- 競技数学の45%→51%に対応する問題集は非公開である。今回はMITライセンスで公開されたGen-Arithmeticと、そのプロンプト実装を使う。
- 元のモデルと同じ得点を再現する実験ではなく、同じ公開算術タスク・10問の例示・フィラー挿入方式を別モデルで追試する実験である。
- [Brauerらの論文](https://arxiv.org/html/2607.03502v2)で行われた内部状態の分析とは、対象と測定項目が異なる。

## 3. 実験1：公開算術タスクでの追試

- モデルの正式API名はGPT-6 Luna。`reasoning_effort=none`、温度0、回答上限100トークンとする。
- 10問の例示を原実装の選択方法で固定する。例示と評価問題の重複を除き、固定した600問を評価する。正解は整数演算で再検算する。
- なし、数列1〜100、数列1〜300、空白区切りの`...`を300個、の4条件を比べる。例示と本問の両方に同じ種類・長さのフィラーを入れる。
- 主比較は「数列1〜100対なし」。残りは追加の探索的比較とする。条件は結果を見る前に固定する。
- 各問の最初の回答を保存して整数の完全一致で採点する。誤答や形式違反を理由に生成し直さない。
- 問題ごとの差を対応づけた信頼区間と、正誤が入れ替わった問題数を示す。

### 掲載する結果

実測値の集計後に、正解率・対照との差・95%信頼区間・改善／悪化した問題数・形式違反数を表にする。改善が確認できなければ、再現成功と書かず、このモデルで期待した効果を確認できなかったことを記す。

## 4. 実験2：音韻検索への応用

- 同じモデルと4種類のフィラー条件を使う。各条件の回答を保存する。
- 既存の音韻検索ベンチマークの150問を使い、100候補から上位10件を選ぶ。
- タスクは音声認識ではなく、文字で与えた発音の似た候補を選ぶ並べ替えである。すべての正解が候補に含まれる条件付きの評価であることも示す。
- 既存の詳細指示・例示1問・JSON形式の出力を用い、例示と本問の回答直前にフィラーを入れる。算術タスクとは例示数と出力形式が異なることを明記する。
- 指標は各問のRecall@10を平均した値とする。数学の正解率とは異なる指標なので、両者の値の大小を直接比較しない。

## 5. 数学と音韻検索で結果はどう違ったか

- それぞれのタスクで「なし」からの変化を比較する。
- 数学だけ改善した場合は、効果がそのまま音韻検索に移るとは限らない、と測定範囲を示す。
- 両方で改善した場合も、別データ・別の例示・別の長さへの一般化は未検証とする。
- 数学で改善しなかった場合は、効果の出る条件をこのモデルで確認できていないことと、音韻検索の評価結果を分けて記す。

## 6. 実用上の判断と残る検証

- 精度の変化と追加の入力トークン数を並べ、得られた改善に見合うかを判断する。
- キャッシュされた入力と未キャッシュの入力を区別する。トークン数をそのまま料金や利用枠の消費とみなさない。
- レイテンシーを測定していなければ、速度への影響は未測定と書く。
- 本実験は振る舞いの測定であり、フィラーの内部状態にどのような計算が保持されているかは検証していない。
- コード、固定した問題、回答、オフラインで再集計する手順を示す。

## 結論の書き方

実測値がそろってから、数学での追試結果、音韻検索への適用結果、採用するかどうかの順に短く述べる。改善することを前提に記事の結論を固定しない。
